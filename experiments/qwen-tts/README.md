# Локальное сравнение Qwen3-TTS и XTTS

## VoiceDesign: управление манерой речи

[Прослушать четыре варианта](output/voice-design/index.html): спокойный
преподаватель, увлечённый популяризатор, неторопливое объяснение и сумасшедший
учёный. Для каждого синтезируются один и тот же связный фрагмент по сопромату
и короткая проба терминов со словом «синусоида». Всего восемь записей.

Используется `Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`, revision
`5ecdb67327fd37bb2e042aab12ff7391903235d3`. Это отдельные веса в том же окружении.
Голосовой образец не подаётся: голос и манера задаются инструкциями из
`voice-design-styles.json`. Инструкции написаны на английском, язык произносимого
текста явно задан как `Russian`. Это пожелания модели, а не подтверждённые
характеристики полученного голоса. Тембр может различаться между генерациями.

```bash
HF_HUB_OFFLINE=1 experiments/qwen-tts/.venv/bin/python experiments/qwen-tts/voice_design.py
python3 experiments/qwen-tts/review_voice_design.py
```

Для первой загрузки убрать `HF_HUB_OFFLINE=1`; модель скачивается автоматически.
Все варианты имеют одинаковые seed 42, настройки сэмплирования модели
(`temperature=0.9`, `top_p=1.0`, `top_k=50`, `subtalker_temperature=0.9`)
и целые абзацы на входе. Меняется только инструкция. Это сравнение четырёх
инструкций, а не проверка стабильности на множестве случайных seed.

Оригинальные WAV сохраняются без монтажа, MP3 для прослушивания выравнивается
до целевых −18 LUFS. На странице также доступен прежний Qwen Base на том же
тексте про балку. Версии пакетов, параметры и время генерации — в
`output/voice-design/report.json`, распознавание — в `speech-check.json`.
`review_voice_design.py` проверяет контрольные суммы исходников и полное
декодирование всех записей. ASR не оценивает интонацию и ударения.

## Base и XTTS: клонирование прежнего образца

Тексты для русского учебного рассказчика: три генерации фрагмента с термином
«синусоида», связное объяснение консольной балки и числа с сокращениями единиц.
Один голосовой образец: `~/project/for-tts-xtts/reference.wav` (12,49 с).
Транскрипция образца в `reference.txt`: Whisper small, с исправлением очевидных
ошибок распознавания по тексту стихотворения. Отдельной ручной проверки записи
на слух не проводилось.

Модель: [Qwen/Qwen3-TTS-12Hz-1.7B-Base](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-Base),
revision `fd4b254389122332181a7c3db7f27e918eec64e3`.
[Официальная библиотека и описание API](https://github.com/QwenLM/Qwen3-TTS).
Используются voice clone с текстом образца, Russian, bfloat16, PyTorch SDPA,
`non_streaming_mode=True`. Параметры сэмплирования — стандартные для модели,
лимит генерации уменьшен до 1600 кодовых кадров. FlashAttention не устанавливался.

## Запуск

Из корня grim (нужны сеть для первой загрузки и доступ к CUDA GPU):

```bash
UV_CACHE_DIR=/tmp/grim-qwen-uv uv venv --python 3.12 experiments/qwen-tts/.venv
UV_CACHE_DIR=/tmp/grim-qwen-uv uv pip install --python experiments/qwen-tts/.venv/bin/python \
  qwen-tts==0.1.1 torch==2.10.0 torchaudio==2.10.0
experiments/qwen-tts/.venv/bin/python -u experiments/qwen-tts/synthesize.py
~/project/for-tts-xtts/venv/bin/python -u experiments/qwen-tts/synthesize.py --engine xtts
python3 experiments/qwen-tts/review.py
```

`review.py` использует установленный в системном Python `faster_whisper`,
локальный кэш small в `/tmp/grim-video-whisper` и `ffmpeg`.
Полный состав установленного окружения сохранён в `requirements.lock.txt`.
После первой загрузки синтез проверен с `HF_HUB_OFFLINE=1`. Для обхода сетевого
запроса токенизатора библиотека получает путь к локальному snapshot, а не ID модели.
При импорте библиотека предупреждает об отсутствии системного SoX и FlashAttention;
используемый здесь путь синтеза успешно работает без них.
Окружение Qwen, веса и результаты находятся внутри этой папки и исключены из Git.
Существующее окружение XTTS не изменяется. `--sample terms` позволяет ограничить
генерацию одним текстом. Существующие WAV пропускаются: для нового эксперимента
с изменёнными параметрами сначала сохраните прежнюю папку `output` под другим именем.

## Результаты и границы проверки

Открыть `output/index.html`: попарные плееры Qwen / XTTS и исходные тексты.
`output/qwen/` и `output/xtts/` содержат все запланированные повторы, без отбора,
обрезки или удаления лишних слов. WAV сохраняется float32, без нормализации;
MP3 для прослушивания выровнен фильтром ffmpeg loudnorm до целевых −18 LUFS.

`report.json` для каждого движка содержит длительности, время синтеза, версии,
seed, хеш образца и пиковую память, выделенную PyTorch. Это не полный расход
видеопамяти процесса. Время загрузки и подготовки голоса записано отдельно.
Первый синтез может включать разогрев. XTTS использует temperature=0.60 и свою
встроенную разбивку длинного текста; Qwen получает абзац целиком.

`speech-check.json` содержит распознавание Whisper и простую долю словных
расхождений. Она не отделяет ошибки синтеза от ошибок ASR, не нормализует числа
и единицы и не проверяет ударения. Качество голоса, интонацию и произношение
«синусоида» следует оценивать прослушиванием. Успешное декодирование всех WAV
проверяется ffmpeg при построении страницы.

## Первый прогон, 13 сентября 2026

На RTX 5090 Qwen создал пять записей общей длительностью 104,96 с за 48,95 с
синтеза, плюс 2,68 с загрузки и подготовки образца. Фрагмент балки — 48,4 с
аудио за 23,24 с. Максимум памяти, выделенной PyTorch: 4,70 GiB.
XTTS на тех же текстах: 97,22 с аудио за 14,32 с синтеза, плюс 13,7 с подготовки.

В трёх пробах терминов Whisper одинаково распознал у Qwen «синусоида»,
«изгибающий момент» и «момент инерции». У XTTS эти места распознавались
нестабильно. В длинном фрагменте у обоих есть расхождения с исходным текстом.
Запись `3,125 мм` у обоих дала подозрительный результат распознавания;
числа и единицы для озвучки по-прежнему следует разворачивать в слова.
Это предварительные наблюдения по ASR, а не заключение о качестве на слух.
