# Изгиб консольной балки: учебный ролик

Уровень начала вузовского курса: наглядная модель, основные формулы и один
проверяемый численный пример. Около четырёх минут, 16 сцен, Full HD, 30 кадров/с,
H.264 + AAC 48 кГц, русский синтетический рассказчик и субтитры.

**[Открыть ролик](output/beam-bending-ru.mp4)**

**VoxCPM2 — два способа озвучки:**

- [Целыми сценами](output-voxcpm-scenes/beam-bending-ru.mp4): 16 цельных записей.
- [По предложениям](output-voxcpm-sentences/beam-bending-ru.mp4): 62 отдельные записи,
  между предложениями добавлено по 0,2 с тишины.

Оба ролика используют один сценарий, рисунки, прежний образец `reference.wav`
и обычное клонирование VoxCPM2 (`reference_wav_path`, без инструкции о стиле
и без режима продолжения). CFG 2.0, 10 шагов диффузии, seed 42 перед каждым
вызовом — как в последней пробе VoxCPM2 с разбиением. Начальная пауза сцены
0,35 с, заключительная 0,8 с в обоих вариантах. Сырые записи не обрезаются.

```bash
bash experiments/beam-bending/run-voxcpm.sh
```

Используется окружение `../voxcpm2/.venv` и сохранённые веса VoxCPM2 без сети.
`synthesize_voxcpm.py --chunking scene|sentence|both` кеширует отдельные записи
с текстом, параметрами и хешами. Каждая версия получает собственные временные
метки и субтитры. Для цельных сцен границы предложений приближённо определяет
`align_scene_cues.py --output-dir ...` по совпавшим словам Whisper; аудио при
этом не режется. Проверка MP4 также сопоставляет исходные WAV с общей дорожкой
посэмплово до нормализации громкости при кодировании.
Первый прогон VoxCPM2: 228,04 с целыми сценами и 228,12 с по предложениям
(с учётом пауз). Синтез занял соответственно 53,94 с и 56,01 с на RTX 5090,
без загрузки модели. Все исходные фрагменты использованы без отбора повторов
или обрезки речевых хвостов. Распознавание помогает обнаруживать пропуски,
но не подтверждает правильность ударений и естественность интонации.

**[Qwen3-TTS: озвучка целыми сценами](output-qwen-scenes/beam-bending-ru.mp4)**

[Предыдущая Qwen-версия: синтез по предложениям](output-qwen/beam-bending-ru.mp4).

Qwen-версия использует тот же сценарий и рисунки, но заново рассчитанные
длительности сцен и субтитров. Модель Qwen3-TTS 1.7B Base получает связный текст
каждой сцены целиком: 16 генераций вместо 62. Это даёт модели контекст соседних
предложений для интонации; внутренних монтажных стыков и добавленных пауз нет.
Голосовой образец прежний. Сырые записи, временные метки, результаты распознавания
и проверки видео находятся в `output-qwen-scenes/`.
Подробности установки Qwen: [эксперимент сравнения TTS](../qwen-tts/README.md).

```bash
bash experiments/beam-bending/run-qwen.sh
```

Скрипт последовательно синтезирует сцены, распознаёт их локальным Whisper,
сопоставляет слова для субтитров, собирает видео и проверяет MP4.
`align_scene_cues.py` сохраняет короткие субтитры по предложениям, используя
временные метки совпавших слов. Для несовпавших слов границы интерполируются:
это приблизительное выравнивание, а не фонетический forced alignment.
В `alignment-report.json` записаны доля совпавших слов и границы каждого титра.
Аудио при выравнивании не меняется. Его исходные интервалы записаны в cues
как `audio_start` / `audio_end` и проверяются при валидации.

Qwen использует сохранённые веса без сети; для синтеза нужен доступ к CUDA.
Отдельные WAV кешируются вместе с текстом, параметрами, версией модели и seed.
В финальном MP4 громкость выравнивается до целевых −16 LUFS.
Прогон целыми сценами: 234,12 с с паузами, синтез 16 фрагментов — 98,46 с
на RTX 5090 (без загрузки модели). Проверка сопоставляет каждый исходный
WAV сцены с соответствующим участком общей дорожки посэмплово: внутри сцены
не добавлены разрывы и не изменена речь. Эта проверка выполняется до нормализации
громкости и сжатия звука в MP4.
Прежний прогон по предложениям: 250,84 с с паузами; синтез 62 реплик занял 105,5 с на RTX 5090
(без загрузки модели). Записи Qwen использованы без обрезки речевых хвостов.
Whisper проверил все реплики; в распознавании есть расхождения в отдельных
словах и окончаниях, поэтому это не подтверждение безошибочного произношения.
Синтез по предложениям доступен через `synthesize_qwen.py --chunking sentence`
и записывает файлы в прежнюю папку `output-qwen/`.

## Содержание

1. Различие между максимумом прогиба и максимумом напряжения.
2. Равновесие правой части после мысленного разреза; сила и плечо.
3. Эпюра величины изгибающего момента.
4. Растяжение верхних и сжатие нижних слоёв при выбранном направлении нагрузки.
5. Нормальное напряжение по высоте и нейтральная ось.
6. Формулы напряжения, момента инерции прямоугольника и прогиба.
7. Численный пример; удвоение силы, длины и высоты по отдельности.
8. Удвоение ширины и высоты при одинаковом увеличении массы.
9. Допущения модели; отдельные проверки прочности и жёсткости.

## Механика и проверка чисел

Используется теория Эйлера — Бернулли: однородная тонкая прямая балка,
малые деформации, линейная упругость, постоянное прямоугольное сечение,
идеальная заделка и сосредоточенная сила вниз на свободном конце.
Собственный вес, деформация сдвига, локальная концентрация напряжений
и потеря устойчивости не моделируются.

Координата x идёт от заделки к свободному концу; y направлена вверх.
Прогиб v отсчитывается вниз. При этих соглашениях:

```text
M(x) = -F (L-x)
σx(x,y) = -M(x)y/I
I = b h³ / 12
v(x) = F x² (3L-x) / (6EI)
δ = v(L) = F L³ / (3EI)
σmax = 6FL / (b h²)
```

На эпюре показана **величина** момента |M|, что подписано в видео.
Растяжение — положительное напряжение, сжатие — отрицательное.
Форма изгиба рассчитывается аналитически; экранное увеличение прогиба
подписано. В сравнительных сценах оно одинаково для обеих балок.

Расчёт ведётся в Н, мм и МПа: F = 200 Н, L = 1000 мм, b = 20 мм, h = 40 мм,
E = 200000 МПа (200 ГПа).

| Вариант | Максимальное напряжение, МПа | Прогиб, мм |
| --- | ---: | ---: |
| Исходный | 37,5 | 3,125 |
| Сила ×2 | 75 | 6,25 |
| Длина ×2 | 75 | 25 |
| Ширина ×2 | 18,75 | 1,5625 |
| Высота ×2 | 9,375 | 0,390625 |

Проверки `mechanics.py` включают численные значения, граничные условия,
знак напряжений и коэффициенты масштабирования. Результат записывается
в `output/mechanics-check.json`. Допустимые напряжение и прогиб в примере
не задаются: вывод о пригодности реальной конструкции не делается.

## Источники формул

- [MIT OpenCourseWare, Solid Mechanics, таблица прогибов, стр. 2](https://ocw.mit.edu/courses/1-050-solid-mechanics-fall-2004/fd4eff39aec922b8c07660006f40686e_pset04_11.pdf):
  форма прогиба и перемещение конца консоли.
- [MIT OpenCourseWare, Linear elastic behavior of a beam, приложение](https://ocw.mit.edu/courses/1-101-introduction-to-civil-and-environmental-engineering-design-i-fall-2006/805ecbc0023c3ab7fb404b9d0c1aeaf1_exp3b.pdf):
  второй момент площади прямоугольника и линейная теория изгиба.
- [David Roylance / MIT, Stresses in Beams](https://eng.libretexts.org/Bookshelves/Mechanical_Engineering/Mechanics_of_Materials_(Roylance)/04:_Bending/4.02:_Stresses_in_Beams):
  нормальные напряжения, нейтральная ось, связь момента и кривизны.

Сценарий и рисунки созданы для этого эксперимента, иллюстрации из источников
не копировались. Связь момента с силой получена из равновесия правой части.

## Пересборка

```bash
bash experiments/beam-bending/run.sh
# Только раскадровка:
python3 experiments/beam-bending/render.py --stills-only
# Повторная сборка из готовой озвучки:
python3 experiments/beam-bending/render.py
# Локальное распознавание для поиска грубых речевых дефектов:
HF_HUB_OFFLINE=1 python3 experiments/beam-bending/verify_speech.py
# Проверка готового MP4, временных меток и чисел:
python3 experiments/beam-bending/validate.py
```

Озвучка использует существующее окружение `~/project/for-tts-xtts/venv`,
установленные веса XTTS v2 и `reference.wav` из того же проекта. XTTS-сервис
не требуется. Генерация происходит локально, исходный проект XTTS не меняется.
Нужен доступ к GPU или достаточно времени для вычисления на CPU.

Для видео используются Pillow, NumPy, Matplotlib (формулы без внешнего LaTeX),
шрифты DejaVu Sans и FFmpeg с libx264. Проверено с Pillow 12.3.0,
NumPy 1.26.4, Matplotlib 3.10.8. Интерпретаторы можно задать через
`XTTS_PYTHON` и `VIDEO_PYTHON`.

Сценарий находится в `script.json`. Каждое предложение генерируется отдельно,
кешируется и получает собственные временные границы в `output/timeline.json`.
Субтитры следуют этим границам; синхронизация по отдельным словам не применяется.
Для другого текста перестраиваются затронутые аудиофрагменты.

В готовой версии у 16 реплик дополнительно убраны посторонние речевые хвосты
после последнего нужного слова. Границы сверены по временным меткам ASR;
оригиналы находятся в `output/before-tail-trim/`, журнал —
`output/tail-edits.json`. Скрипт `trim_tails.py` сначала показывает предлагаемые
срезы для явно перечисленных файлов; `--apply` применяет их. Это отдельная
редакторская операция, не автоматическая часть `run.sh`. Пока WAV-кеш сохранён,
повторная сборка использует отредактированное аудио. Генерация с нуля потребует
новой проверки речи.

`verify_speech.py` использует уже скачанный Whisper small из
`/tmp/grim-video-whisper`. Распознавание выявляет грубые пропуски и повторы,
но **не подтверждает правильность ударений или интонации**. XTTS остаётся
экспериментальным рассказчиком; весь комплект WAV сохранён для точечной замены.

Все результаты находятся в `output/`, исключены из Git. Это самостоятельный
прототип на Python/Pillow, без изменения Grim и без зависимости от Manim.
