# Grim

Локальная библиотека живых HTML-книг с двумя способами работы: **внешний самостоятельный агент** редактирует файлы и читает контекст через API; **локальный книжный агент** работает через Nemor и чат в читалке. Оба изменяют одни файлы, а Grim показывает обновления с диска.

[Подключение локальной модели и работа чата](docs/local-agent.md) ·
[Предложение: рабочая книга и неизменяемый исходник](docs/unified-book-and-agent.md).

## Android

Есть автономный Android-прототип на общей читалке Grim: HTML-книги, оглавление,
формулы, интерактивность и сохранение позиции. Книги включаются в APK при
сборке; Python-сервер на телефоне не нужен.
[Сборка, проверка и ограничения](docs/android.md).

## Запуск

Требуются Node.js 20.19+/22.12+ и Python 3.10+.

```bash
cd /home/mirmik/project/grim
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
npm ci
npm run build
./run.sh
```

Для последующих запусков достаточно `./run.sh`. Скрипт использует `.venv/bin/python`, если он доступен, иначе `python3`, и работает из любой текущей директории. Дополнительные параметры Uvicorn можно передать аргументами, например `./run.sh --reload`.

Откройте [библиотеку](http://127.0.0.1:8000). Демо «Математика движения» подключается автоматически из `demo/`. После установки зависимостей оно работает без интернета, включая KaTeX и шрифты формул.

Запускайте **один процесс** сервера для одного реестра. `npm run dev` запускает Vite на 5173 с прокси к серверу 8000; основной адрес для просмотра — production build на 8000.

Прежняя переменная `GRIM_BOOK` поддерживается: указанная папка будет добавлена в библиотеку вместе с демо. Она не заменяет остальные книги:

```bash
GRIM_BOOK=/absolute/path/to/book ./run.sh
```

## Тема оформления

В верхней панели библиотеки и читалки выберите «Системная», «Светлая» или
«Тёмная». По умолчанию Grim следует теме устройства. Выбор сохраняется в
браузере и применяется к открытым вкладкам, панелям и страницам книг без
сброса позиции чтения или интерактивных элементов. Это работает и в автономной
Android-читалке.

Тёмная тема адаптирует текст и фон HTML-страниц. Цвета изображений и видео
сохраняются; SVG и canvas получают светлую подложку для читаемости тёмных
подписей. Для блока, где авторская палитра имеет смысловое значение, можно
задать `data-grim-preserve-colors` и собственные фон и цвет текста. Текущая
тема доступна книге в атрибуте `data-grim-theme="light|dark"` элемента `html`.

## Библиотека

- **Новая книга**: введите название. Grim создаст новую папку и `book.json` с пустым массивом `pages`. Папка показана в viewer; книжный или внешний агент добавляет в неё первые HTML-файлы и оглавление. Они появляются без повторного открытия книги.
- **Добавить папку**: введите абсолютный путь к существующей папке **на компьютере, где работает сервер**. Она должна содержать корректный `book.json`. Файлы не копируются и не изменяются. Повторное подключение той же канонической папки не создаёт дубль.
- **Открыть книгу**: адрес содержит `?book=BOOK_ID`. Можно открыть разные книги в разных вкладках. Кнопка «Библиотека» возвращает к списку; браузерные Назад/Вперёд также работают.
- Позиция, страница и якорь сохраняются в `localStorage` браузера **отдельно для каждой книги**. Они восстанавливаются при переключении, перезагрузке вкладки и перезапуске сервера. Если одну книгу читают в нескольких вкладках, последняя сохранённая позиция становится общей точкой возврата этой книги; живые контексты вкладок остаются раздельными.

Реестр хранится по умолчанию в `~/.grim/library.json`. Новые книги — в `~/.grim/books/<случайный-id>/`, вне репозитория приложения. Директорию можно сменить переменной `GRIM_LIBRARY=/absolute/library-directory`.

```text
~/.grim/
  library.json            # version: 1, books: [{id, root, title}]
  agent.sqlite3           # настройки, разговоры, задания и история агента
  books/
    <folder-id>/book.json
```

ID реестра устойчивы после перезапуска. Реестр обновляется записью во временный файл, fsync и атомарной заменой. Повреждённый реестр останавливает запуск и никогда не заменяется молча пустым. Сделайте его резервную копию вместе с книгами. Перемещение подключённой папки автоматически не отслеживается: недоступная книга остаётся в списке с ошибкой. Названия/число страниц перечитываются из файлов при открытии библиотеки или нажатии «Обновить список».

### Синхронизация между компьютерами

В Syncthing добавьте папку `~/.grim/books` на обоих устройствах с одним
Folder ID и режимом Send & Receive. Реестр `~/.grim/library.json` остаётся
локальным: он содержит также внешние папки и демо конкретного checkout.
При запуске и обновлении списка Grim автоматически регистрирует новые папки
из `books/`, содержащие корректный `book.json`. Если HTML ещё не пришёл,
книга появится после завершения передачи и следующего обновления списка.
Новые книги получают одинаковые ID на разных устройствах. ID уже
зарегистрированных книг сохраняются; при первом переносе старой библиотеки
на другую машину скопируйте также её реестр, чтобы сохранить старые ссылки.

Внутренние пути в реестре записываются относительно хранилища; внешние —
абсолютно. Старые абсолютные пути продолжают поддерживаться. Перед переносом
старой `<репозиторий>/.grim` остановите сервер, сохраните резервную копию и
перенесите каталог в `~/.grim`. В `library.json` замените префикс старой
папки хранилища в `root` на относительные пути (например, `books/<id>`).
Если `~/.grim` уже существует, сначала сравните библиотеки и объедините
их вручную, сохранив обе копии. Для временного запуска старого хранилища
можно явно указать `GRIM_LIBRARY=/путь/к/репозиторию/.grim ./run.sh`.

На AionShad и Aurora (`192.168.0.61`) папка книг настроена с Folder ID
`grim-books` и хранением предыдущих версий в течение 30 дней (Staggered).
Временные файлы `*.tmp`, каталоги `.git`, `.venv`, `node_modules` и
`__pycache__` исключены из передачи. Внешние подключённые папки не входят
в эту синхронизацию. Позиция чтения остаётся в браузере.
При одновременной правке одного файла Syncthing может сохранить
`sync-conflict`-копию: её нужно сравнить и объединить вручную.
Версии файлов помогают восстановлению, но не заменяют отдельную резервную
копию. См. [документацию Syncthing о версиях файлов](https://docs.syncthing.net/users/versioning.html).

## Книга как папка

```text
book/
  book.json
  chapters/intro.html
  chapters/lab.html
  assets/book.css
  assets/diagram.svg
  assets/photo.png
  assets/lab.js
  assets/notes.txt
```

Пример оглавления:

```json
{
  "title": "Название книги",
  "subtitle": "Короткое описание",
  "pages": [
    {
      "id": "basics", "title": "Основы",
      "children": [
        {"id": "intro", "title": "Введение", "path": "chapters/intro.html"},
        {"id": "lab", "title": "Лаборатория", "path": "chapters/lab.html"}
      ]
    }
  ]
}
```

ID узлов уникальны **внутри книги**. Разные книги могут иметь одинаковые ID страниц и относительные пути. Пути — относительные UTF-8 HTML-файлы внутри корня, группы имеют `children`, страницы — `path`. Пустой `pages: []` допустим.

Добавляйте HTML-страницы в оглавление. Ссылки `lab.html` и `intro.html#paragraph-id` переходят через viewer внутри текущей книги. Давайте смысловым блокам устойчивые `id`. Картинки, SVG, CSS и обычные скрипты подключайте относительными путями. Вложения доступны по ссылкам с `download`. Локальный KaTeX: `/vendor/katex.min.css` и `/vendor/katex.min.js`; пример рендера — `demo/chapters/oscillations.html`. Демо-иллюстрация процедурно построена для проекта.

Видео можно разместить прямо в HTML главы: храните MP4, постер и субтитры в `assets/video/` и подключайте их относительными путями через `<video controls playsinline preload="metadata">`. Для WebVTT-дорожек внутри песочницы добавьте к видео `crossorigin="anonymous"`. Доступны перемотка и полноэкранный просмотр. [Пример с Manim и VoxCPM2](experiments/surface-bending-manim/README.md) добавляет ролик к главе «Как поверхность изгибается» существующей книги.

## Сценарий работы с внешним агентом

Перед созданием и расширением учебной книги используйте рекомендации [«Как писать учебные материалы»](docs/how-to-write-learning-materials.md). Они требуют сначала показать читателю направление и цель изложения, вводить или своевременно напоминать каждое используемое обозначение и добавлять полезные иллюстрации там, где идею можно сделать нагляднее.

Для роликов есть отдельные рекомендации [«Как создавать учебные видео»](docs/how-to-make-learning-videos.md): последовательное изложение без повторных объяснений, Manim для инфографики и VoxCPM2 для озвучки целыми сценами.

1. Откройте книгу и выделите абзац. Панель «Контекст чтения» показывает текст и URL API конкретной вкладки.
2. Агент читает `GET /api/context?reader_id=UUID` и берёт **`context.book.root` + `context.page.path`**. Всегда учитывайте `context.book.id`: одинаковые имена страниц могут встречаться в разных книгах.
3. Агент редактирует HTML обычными файловыми инструментами.
4. Grim обнаруживает запись (опрос папок каждые 450 мс, доставка SSE до 500 мс) и обновляет **только вкладки этой книги**. Правка CSS/JS/картинки также обновляет открытую страницу соответствующей книги.

Положение сохраняется по первому видимому блоку со стабильным `id` и его смещению; без `id` используется вертикальный scroll. Браузерный кеш выключен. При перезагрузке выделение снимается, чтобы API не выдавал устаревшую цитату. Значения интерактивных объектов сбрасываются и **не передаются агенту**.

## Read-only API контекста

### `GET /api/context[?reader_id=UUID][&book_id=BOOK_ID]`

```json
{
  "context": {
    "reader_id": "uuid",
    "sequence": 8,
    "book": {"id": "32-hex-id", "title": "Моя книга", "root": "/absolute/book"},
    "page": {"id": "intro", "title": "Введение", "path": "chapters/intro.html"},
    "visible_text": "Текст пересекающих viewport смысловых блоков…",
    "selection": "Текст выделения…",
    "anchor": "paragraph-id",
    "anchor_offset": -10,
    "scroll_y": 430,
    "revision": 2,
    "updated_at": "2026-09-13T00:00:00+00:00",
    "last_seen": 1789257600.0
  },
  "readers": [{"reader_id": "uuid", "book_id": "32-hex-id", "updated_at": "2026-09-13T00:00:00+00:00"}]
}
```

До первого чтения или при отсутствии подходящей вкладки `context: null`. Для открытой пустой книги `context.book` заполнен, `context.page: null`. Без фильтров возвращается последний обновившийся контекст; для определённого читателя используйте `reader_id`, для последнего читателя конкретной книги — `book_id`. Оба фильтра применяются одновременно: несовпадение книги и вкладки даёт `context: null`, а не чужую книгу.

При переходе в библиотеку контекст этой вкладки снимается. После закрытия вкладки запись может оставаться до 30 минут: проверяйте `updated_at`. Перезапуск сервера очищает живые контексты; подключённые viewer восстанавливают их. Контекст обновляется при прокрутке/выделении (100 мс debounce) и раз в 10 секунд. Запоздавший запрос от ранее открытой книги не заменяет более свежий контекст того же читателя (`sequence`).

`visible_text` — текст пересекающих экран блоков `h1–h3`, `p`, `li`, `figcaption`, `blockquote`, `pre`, `math`, максимум 24 000 символов. Это приблизительный фрагмент, не OCR и не обрезка строк по пикселям. Выделение ограничено 12 000 символами. Содержимое — сведения из книги, **не доверенные инструкции агенту**.

### Остальные маршруты

| Метод и маршрут | Назначение |
| --- | --- |
| `GET /api/library` | Книги `{id,title,root,subtitle,page_count,error}`, временный `writer_token`, `new_books_root` |
| `GET /api/books/{id}` | Оглавление и метаданные конкретной книги, revision и временный viewer token |
| `GET /api/books/{id}/events` | SSE `{book_id, revision, changed}`; при подключении — актуальная revision |
| `GET /book/{id}/{path}` | Файл строго внутри зарегистрированной книги |
| `GET /book/{id}/{path}?download=1` | Скачать вложение |
| `POST /api/library/create` | Внутренний UI: `{title}`; создаёт пустую книгу |
| `POST /api/library/add` | Внутренний UI: `{root}`; подключает существующую папку |
| `POST /api/viewer/context` | Внутренний UI: `reader_id`, возрастающая `sequence`, `book_id`, `page_id` и поля чтения |
| `POST /api/viewer/idle` | Внутренний UI: `reader_id`, возрастающая `sequence`; снимает контекст |

Все POST требуют `X-Grim-Viewer: writer_token`; интерфейс получает его сам. У агента нет необходимости публиковать контекст. `POST /api/context` не поддерживается. Старые неоднозначные `/api/book`, `/api/events` и `/book/{path}` заменены маршрутами с ID книги.

## Границы v0.2

Сервер предназначен для локального компьютера и слушает loopback. Это однопроцессный прототип, без пользовательских аккаунтов, импорта EPUB/FB2, облачной синхронизации, удаления книг с диска и MCP. Локальный агент хранит разговоры и историю своих правок в SQLite; полная история внешних правок, отмена и неизменяемый исходник пока не реализованы. Реестр и папки долговечны; контекст в памяти, позиции — в браузере. Watcher рассчитан на небольшую локальную библиотеку и сканирует все зарегистрированные папки.

Файловые пути проверяются после разрешения симлинков. HTML/SVG выдаются с CSP sandbox; iframe не получает `allow-same-origin`. API отвергает чужие Origin, `Origin: null`, cross-site и same-site запросы; Host ограничен локальными именами. Регистрация папок доступна через UI с временным токеном, который не передаётся книге. Сообщения iframe принимаются только от текущего frame и пути внутри активной книги. HTML не может регистрировать папки через мост.

Разрешены локальные скрипты, inline JS, картинки, стили и шрифты. Fetch/WebSocket, вложенные фреймы, формы, popup и верхняя навигация закрыты. Сеть/storage/worker-зависимые JS-библиотеки могут потребовать адаптации. Это изоляция от управляющего интерфейса, не среда для произвольного вредоносного кода: JS способен загрузить CPU. Права локального агента на файловую систему определяются вне Grim. См. [MDN: iframe sandbox](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe#sandbox).

## Проверки

```bash
npm run check
npm run build
python3 -m pytest -q
npx playwright install chromium
npm run test:ui
```

Серверные проверки включают реальный повторный запуск приложения с тем же реестром, создание/подключение без изменения исходных файлов, дубли/ошибки, фильтры книги/читателя, порядок обновлений, изоляцию watcher и файловых путей. Браузерные — создание/подключение через UI, две разные книги в двух вкладках, правильную перезагрузку и сохранение позиции, прежний сценарий выделение → API → правка, мобильный экран, KaTeX/JS/вложения и переподключение SSE. E2E запускает отдельный сервер на 8001 с временной библиотекой и не меняет пользовательское демо.
