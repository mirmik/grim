# Локальный книжный агент

Grim поддерживает два способа работы одновременно:

- Внешний самостоятельный агент читает `/api/context` и изменяет обычные
  файлы книги. Инструкция в [README](../README.md#сценарий-работы-с-внешним-агентом).
- Книжный агент работает внутри сервера Grim на компьютере через
  `nemor.core.Agent`. Читатель общается с ним в панели «Чат с агентом».

Оба работают с одними HTML, `book.json` и ресурсами. Изменения показывает
существующий watcher. Android-приложение может подключаться к этому сервису;
автономные книги на устройстве читаются без локального агента.

## Установка и подключение модели

После обычной установки Grim добавьте текущий соседний checkout Nemor:

```bash
cd /home/mirmik/project/grim
uv pip install --python .venv/bin/python --no-deps -e ../nemor
npm run build
./run.sh
```

Здесь используется библиотечный `nemor.core`, которому достаточно стандартной
библиотеки Python. Зависимости отдельного приложения Nemor не требуются.
Проверенный контракт — `Agent(completion=…, session=…, tools=…, config=…)`
из соседнего checkout на 2026-09-15. Старые импорты Coreader
`nemor.core.agent`/`AgentApplication` не используются. Без Nemor библиотека
и внешний агент работают; чат показывает, что runtime нужно установить.

Для существующего окружения обновите также зависимости Grim:
`uv pip install --python .venv/bin/python -r requirements.txt`.
Поиск использует DDGS, извлечение HTML — Trafilatura и Beautiful Soup,
чтение текстовых PDF — pypdf. Зависимости приложения Nemor для этого не нужны.

Откройте книгу → «Чат с агентом» → настройки:

1. Укажите адрес OpenAI-совместимого сервера модели, например
   `http://127.0.0.1:8080/v1`. Модель должна поддерживать function calling
   через `POST /v1/chat/completions`.
2. Введите имя модели и, если требуется серверу, API-токен.
3. Для частного HTTPS-сервера можно указать **Fingerprint сертификата SHA-256**:
   64 hex-знака или 32 пары через двоеточие. Получите его у владельца сервера
   или из доверенного локального сертификата. Например:

   ```bash
   openssl x509 -in /path/to/server.crt -noout -fingerprint -sha256
   ```

   Указанный fingerprint становится способом проверки сервера: Grim сверяет
   SHA-256 фактического сертификата до отправки HTTP-запроса и API-токена,
   в том же TLS-соединении. Проверка центра сертификации, срока сертификата
   и соответствия DNS/IP заменяется точным совпадением fingerprint. Это
   позволяет использовать самоподписанный сертификат и LAN-адрес.
   Поле требует `https://`; пустое поле сохраняет обычную проверку HTTPS.
   При смене сертификата подключение отвергается до обновления fingerprint
   по доверенному источнику. HTTP-редиректы не выполняются. В режиме
   fingerprint Grim подключается напрямую, без прокси из переменных окружения.
4. Нажмите **Сохранить и проверить**: Grim сохраняет введённые настройки,
   запрашивает `/models` и показывает доступные имена. Это проверка доступности сервера,
   а не качества инструментальных вызовов модели.
5. Закройте настройки кнопкой ⚙ и отправьте сообщение. Например:
   «Прочитай этот раздел и добавь один пример после определения».

Адрес относится к компьютеру с Grim. Запуск и загрузка самой модели остаются
за её сервером. Настройки общие для локального Grim; внутри каждой книги
можно вести несколько отдельных чатов. Можно задать указания агенту, предел
токенов ответа, число шагов и таймаут отдельного запроса.

## Новый чат и прежние разговоры

**Начать новый чат** создаёт пустую беседу в текущей книге. Прежняя история
сохраняется и не передаётся модели в новом чате. Кнопка **Старые чаты**
показывает беседы этой книги; выберите нужную, чтобы продолжить её историю.
Название чата берётся из первого сообщения. Черновики при переключении
сохраняются в открытой панели; выбранный чат переживает перезагрузку вкладки.
Разные открытые вкладки могут выбирать разные чаты одной книги.

Переключение не отменяет запущенное задание: оно дописывает ответ и историю
в свой исходный чат. На книгу по-прежнему допускается одно активное задание.
Если оно выполняется в другой беседе, панель предлагает открыть этот чат;
отправить следующее задание можно после завершения или остановки текущего.

При первом запуске новой версии прежние разговоры, задания и история правок
связываются с отдельными чатами автоматически, с сохранением ID и сообщений.
Старая таблица `sessions` остаётся в БД; новые беседы хранятся в `chats`.
Перед обновлением сервиса сделайте резервную копию `agent.sqlite3`.

## Компактизация и системные инструкции

**Компактизировать чат** вызывает настроенную модель, чтобы заменить старую
часть модельного контекста краткой сводкой. Последние два пользовательских
обмена сохраняются целиком, включая инструментальные вызовы, результаты и
снимки книги. Сводка должна сохранить решения, термины, стиль, ограничения,
незавершённые задачи и имена записок. Файлы книги и записки не меняются.
Это ручное сжатие: автоматического бюджета контекста пока нет. Если история
уже превышает лимит модели, запрос сводки тоже может завершиться ошибкой.

Операция отображается в чате и допускает **Остановить**. Запись сводки и
архивирование прежнего контекста выполняются одной транзакцией SQLite.
При ошибке модели, пустом/оборванном ответе, отмене или более длинной сводке
прежний контекст сохраняется. Пока операция выполняется, новые запросы и
обновление инструкций для этой книги недоступны. Переключать чаты можно.
Список прежних сообщений остаётся в интерфейсе; сжимается только контекст
модели. Полный контекст до замены доступен через API архивов. Архивы содержат
в том числе результаты инструментов; отдельной кнопки восстановления пока нет.
Перезапуск не повторяет незавершённую компактизацию автоматически.

**Обновить системные инструкции** сразу записывает в существующую сессию
актуальные правила Grim и сохранённые указания из настроек, сохраняя весь
остальной контекст. Модель не вызывается. Перед применением своих новых
указаний сохраните настройки. Независимо от кнопки свежие системные указания
автоматически подставляются перед каждым следующим сообщением. Изменение
инструкций не меняет прошлый фактически отправленный запрос: в отладчике
смотрите **Следующий запрос**.

## Оформление ответов

Ответы агента отображаются как Markdown: абзацы, заголовки, жирный и курсивный
текст, цитаты, обычные и нумерованные списки, зачёркивания, код и таблицы.
Для кода и широких таблиц доступна горизонтальная прокрутка внутри ответа;
панель сохраняет ширину на телефоне. Оформление использует текущую тему.
Ссылки HTTP(S) открываются отдельно. Внешние изображения показываются
ссылками, без автоматической загрузки.

Так отображаются и уже сохранённые ответы: история по-прежнему хранит
исходный текст, повторно спрашивать агента не нужно. Пользовательские
сообщения и выделенные цитаты остаются обычным текстом. HTML из ответа
показывается буквально, затем результат Markdown проходит очистку перед
выводом; скрипты, обработчики событий и опасные URL не исполняются.

## Контекст и инструменты

Сообщение сохраняет версию (`working` или `source`), страницу, выделение, видимый текст, якорь, ID читателя
и текущий номер обновления viewer. Снимок не меняется при прокрутке.
Сервер добавляет название исходной книги, название читаемой версии,
подзаголовок, автора/авторов, описание или аннотацию, если они есть в
`book.json`, а также название и путь текущей главы, число страниц и первые
60 пунктов оглавления. Для более длинного оглавления указано
`outline_truncated`; целиком его можно прочитать инструментом `book_read`.
При импорте EPUB сохраняются авторы и `dc:description`. Для прежних книг
описание не придумывается и автоматически не восстанавливается.
Эти сведения включаются в пользовательское сообщение как данные книги,
поэтому агент знает её название с первого запроса, без отдельного вызова
инструмента. Версия и метаданные фиксируются при приёме сообщения сервером.
`reading_context` также возвращает свежий контекст **этой же вкладки и книги**,
если она ещё открыта. Книжный текст обозначается как данные.
В режиме чтения рядом нажатие или выделение выбирает колонку; контекст
сообщения относится к выбранному оригиналу или рабочей копии. Для сохранения
выравнивания при переводе сохраняйте ID страниц и HTML-блоков; явное
соответствие нового блока оригиналу задаётся `data-grim-source="ID"`.

| Инструмент | Действие |
| --- | --- |
| `reading_context` | Снимок при отправке и текущий контекст |
| `book_read` | Окно строк UTF-8 файла и SHA-256 всего файла |
| `book_search` | Текстовый поиск внутри книги |
| `book_replace` | Замена одного точного уникального фрагмента |
| `book_write` | Создание или полная замена текстового файла |
| `book_guidance` | Руководства проекта для учебных книг и видео |
| `notes_list` | Список общих записок книги |
| `notes_read` | Полный текст записки и её SHA-256 |
| `notes_create` | Создание записки со свободным содержимым |
| `notes_update` | Полная замена записки с проверкой SHA-256 |
| `notes_delete` | Удаление записки с проверкой SHA-256 |
| `web_search` | Поиск в публичном интернете: заголовки, URL и сниппеты |
| `fetch_webpage` | Чтение HTML, текста и PDF; ссылки, поиск фразы, продолжение длинного документа |

`book_read` и `book_search` принимают необязательный `version`: по умолчанию
`working`, для основного документа после создания копии — `source`.
Основной документ остаётся в корне и проверяется по SHA-256; копия хранится
в отдельной видимой папке, которую можно переименовать через UI. `book_write` и `book_replace` всегда
изменяют рабочие файлы, даже если читатель смотрит оригинал. Перед записью
нужно читать `working`. Каждый чат принадлежит книге; версия каждого сообщения
сохраняется в его контексте. Внешний агент получает читаемую папку в
`book.root`, папку для правок — в `book.working_root`.

## Интернет-поиск и чтение источников

Агент может искать дополнительный контекст и открывать страницы независимо
от файлов книги. Например: «Найди происхождение этого термина, прочитай
первичный источник и объясни его значение здесь со ссылкой».
Поисковый запрос передаётся поисковым сервисам; файл книги и модельный
API-токен инструменты автоматически не передают.

`web_search` принимает `query`, `limit` (1–10, по умолчанию 5), `page`
(1–10), `region` (например `ru-ru`, `us-en`, по умолчанию `wt-wt`) и
`timelimit`: `d`, `w`, `m`, `y`. Можно использовать запросы `site:domain`.
Возвращаются заголовок, URL и краткое описание каждого результата.
Пустая выдача отличается от ошибки или ограничения поискового сервиса.
DDGS выбирает доступные поисковые движки; отдельный ключ поиска не нужен.

`fetch_webpage` загружает публичный HTTP(S) URL с проверкой TLS и
перенаправлений, извлекает основной текст и до 100 ссылок. Поддерживаются
HTML, текстовые документы и PDF с текстовым слоем. Сохраняются название,
исходный и конечный URL, время загрузки и способ извлечения. Если основной
текст не выделен, используется видимый текст страницы с явным
`extraction="visible_text_fallback"`.

За вызов возвращается до `max_chars` символов (по умолчанию 16 000,
диапазон 1 000–32 000). Для продолжения агент использует `document_id`,
тот же URL и `start=next_start`. Это чтение неизменной загруженной копии,
а не повторная загрузка меняющейся страницы. Необязательный `query`
находит фразу в извлечённом тексте и возвращает окно вокруг первого
совпадения и позиции первых 20 совпадений. Копии живут 10 минут,
в памяти держатся последние 16 документов. После перезапуска или вытеснения
копии нужно начать чтение URL заново.

Лимиты: загрузка и распакованное тело — 5 МБ; извлечённый документ —
1 млн символов; PDF — первые 200 страниц. Ограничение документа отмечается
`document_truncated`, границы порции — `start`, `next_start`, `total_chars`.
Превышение лимита загрузки возвращает ошибку. Сервис не исполняет JavaScript,
не входит на сайты, не обходит CAPTCHA/платный доступ и не делает OCR сканов.
Некоторые сайты и поисковики могут ограничивать автоматические запросы.

Инструменты не используют токен, fingerprint или соединение модельного
сервера, не передают cookie/авторизацию и не обращаются к локальным адресам,
LAN или служебным сетям. Для каждого редиректа DNS проверяется заново;
соединение идёт на уже проверенный адрес с исходным HTTPS-именем. Прямое
чтение страниц не использует прокси из окружения и сторонний Reader.

Системная памятка предписывает открывать источник перед цитированием,
ссылаться на конкретные страницы и отличать внешние сведения от книги.
Текст сайтов и сниппеты считаются данными. В панели видны действия
«Ищет в интернете» / «Читает веб-страницу», ссылки в ответах кликабельны.
Через **Контекст агента** доступны фактические результаты инструментов.

## Записки агента

У каждой книги есть одно свободное хранилище: обычные UTF-8 файлы в
`.grim-agent-notes/` в корне подключённой книги. Это общие записи для всех её
чатов, оригинала и рабочей копии. Создание или переименование рабочей копии
не переносит и не дублирует записки. Они сохраняются между перезапусками;
для переноса достаточно скопировать папку вместе с книгой.

Агент сам выбирает имена и содержимое: например, `translation.md` с именами,
терминами и договорённостями о стиле или `questions.txt` с открытыми вопросами.
Фиксированной схемы и подтверждения отдельных записей нет. Имя — один файл
без подпапок и скрытого префикса, до 200 байт UTF-8. Полный текст — до
64 000 байт; чтение никогда не возвращает усечённую записку. Внешний агент
или редактор может работать с этими же файлами напрямую.

Системная памятка объясняет инструменты и предлагает агенту при начале чата
или продолжении работы посмотреть список и прочитать подходящие записи,
а затем поддерживать полезный контекст. Автоматически весь текст записок
в запрос не включается. Фактические вызовы и прочитанное содержимое видны
в истории инструментов и через **Контекст агента**.

Создание не перезаписывает существующее имя. Для обновления и удаления нужен
`expected_sha256` из `notes_read`; конфликт требует перечитать файл.
Изменения сервиса сериализованы общей блокировкой книги; сохранение атомарно.
Для прямых внешних правок действует та же оптимистическая гарантия, что у
книжных файлов: небольшое окно между проверкой хеша и заменой остаётся.
Записки не входят в снимок оригинала и не вызывают перезагрузку страницы.
Отдельной истории версий записок нет; их текущее содержимое хранится в файлах.

## Просмотр контекста

Кнопка **Контекст агента** открывает сведения о книге и JSON запроса:

- **Следующий запрос** — предпросмотр с текущими сохранёнными настройками,
  историей выбранного чата, черновиком и местом чтения. Кнопка
  **Обновить контекст** перечитывает их. Предпросмотр не обращается к модели
  и не создаёт задание.
- **Последний отправленный** — фактические `model`, `messages`, `tools` и
  параметры последнего вызова модели в этом чате, с временем и номером шага.
  Сюда входят системные указания, сообщения и результаты инструментов.
  Последний ответ модели может ещё не входить в этот исходящий запрос.

Снимок фиксируется непосредственно перед вызовом completion, после подготовки
сообщений Nemor. Хранится один последний запрос на чат; предыдущие шаги
не образуют отдельный архив. Для запросов, выполненных до этого обновления,
фактического снимка нет — доступен предпросмотр сохранённой истории.
Заголовки авторизации и настройки API-токена в снимок не включаются.

Запись ограничена текущей книгой и текстовыми форматами: HTML, CSS, JS,
SVG, JSON, TXT, Markdown, CSV и субтитры. Максимум файла — 1 МБ.
Симлинки, скрытые пути и выход из корня запрещены. Для существующего файла
нужен хеш, полученный при чтении; для нового — `null`. `book.json` проверяется
до записи, поэтому новые HTML-страницы нужно создать перед их регистрацией.
Исполнения shell и генерации бинарных изображений/видео в этих инструментах нет.

Хеш обнаруживает устаревшую правку. Записи самого сервиса сериализованы для
каждой книги; файл заменяется атомарно. Произвольный внешний редактор не
участвует в блокировке: остаётся узкое окно между последней проверкой и
заменой файла. Это оптимистическая проверка, не транзакция со всеми внешними
процессами. Несколько файлов также не образуют одну транзакцию.

## Сохранение, остановка и история

В `GRIM_LIBRARY/agent.sqlite3` (обычно `~/.grim/agent.sqlite3`) сохраняются
настройки, разговоры, задания и прежние тексты файлов. Токен модели хранится
в этой локальной БД с правами `0600`; API возвращает лишь `has_token`.
БД не входит в синхронизируемую папку `books/`. Для её резервной копии
остановите сервер и скопируйте БД вместе с реестром и книгами.

Принятое задание продолжает работу после закрытия чата или вкладки.
Повтор того же `job_id` с тем же содержимым возвращает существующее задание;
другое содержимое с этим ID отвергается. На книгу допускается одно активное
задание. После перезапуска незавершённые задания помечаются `interrupted`
и автоматически не повторяются: часть правок уже могла попасть на диск.
Nemor восстанавливает допустимую последовательность сообщений при оборванном
вызове инструмента, без повторного исполнения этого инструмента.

«Остановить» запрашивает остановку после текущего действия. Ожидающий HTTP
ответ модели может завершаться до своего таймаута; уже записанные правки
остаются. Предел шагов или отсутствие ответа показываются как ошибка,
даже если агент успел изменить файлы.

До замены файла сохраняются полный прежний и новый тексты. Статус `applied`
означает успешную запись; `prepared` или `uncertain` после аварии требуют
сравнения с текущим файлом. История доступна через API ниже. Интерфейса
сравнения и отмены пока нет. Прямые файловые правки внешнего агента watcher
показывает, но эта история их ещё не архивирует.

## API

Все изменяющие запросы требуют `X-Grim-Viewer` из `/api/library`.
Сохраняется локальная граница Host/Origin; публиковать этот прототип в LAN
без отдельного механизма подключения не следует.

| Метод и путь | Назначение |
| --- | --- |
| `GET /api/agent/settings` | Настройки без токена, доступность runtime |
| `PUT /api/agent/settings` | Сохранить настройки; пустое поле токена в UI сохраняет прежний |
| `POST /api/agent/probe` | Список моделей на сохранённом endpoint |
| `GET /api/books/{id}/agent?chat_id=…` | Выбранный чат, его задания, список чатов и ID беседы с активным заданием |
| `POST /api/books/{id}/agent/chats` | Создать новый чат |
| `POST /api/books/{id}/agent/chats/{chat_id}/activate` | Выбрать прежний чат |
| `POST /api/books/{id}/agent/chats/{chat_id}/refresh-system` | Применить свежие системные инструкции, без вызова модели |
| `POST /api/books/{id}/agent/chats/{chat_id}/compact` | `{job_id}` — запустить ручное сжатие, повтор с тем же ID безопасен |
| `GET /api/books/{id}/agent/chats/{chat_id}/archives` | Список архивов контекста; требует `X-Grim-Viewer` |
| `GET /api/books/{id}/agent/chats/{chat_id}/archives/{operation_id}` | Полный прежний контекст, включая результаты инструментов; требует `X-Grim-Viewer` |
| `POST /api/books/{id}/agent/context` | `{chat_id, reader_id, message, context}` — предпросмотр и последний фактический запрос |
| `GET /api/books/{id}/agent/notes` | `{notes: [{name, bytes, updated_at}]}` — список записок |
| `POST /api/books/{id}/agent/notes` | `{name, content}` — создать, HTTP 201 |
| `GET /api/books/{id}/agent/notes/{name}` | `{name, content, sha256, bytes}` — прочитать |
| `PUT /api/books/{id}/agent/notes/{name}` | `{content, expected_sha256}` — заменить |
| `DELETE /api/books/{id}/agent/notes/{name}` | JSON-тело `{expected_sha256}` — удалить |
| `POST /api/books/{id}/agent/jobs` | `{job_id, chat_id, message, reader_id, context}` |
| `POST /api/books/{id}/agent/jobs/{job_id}/stop` | Запросить остановку |
| `GET /api/books/{id}/agent/history` | Последние 100 управляемых правок |
| `GET /api/books/{id}/agent/history/{edit_id}` | Полные тексты до/после правки |

Первый срез получает ответ целиком и опрашивает состояние раз в секунду.
Без `chat_id` старые клиенты используют выбранный по умолчанию чат книги;
принятое задание всегда закреплено за конкретным чатом. Чаты других книг
нельзя открыть или использовать по их ID. Потоковой выдачи токенов и ветвления
пока нет. Ручное сжатие доступно кнопкой; автоматический бюджет контекста
и пагинация больших списков остаются отдельной задачей. На больших разговорах
можно упереться в контекстное окно модели.
Текущая [система рабочих копий](../README.md#основной-документ-и-рабочая-копия)
описана отдельно от [будущей модели истории](unified-book-and-agent.md).

## Проверка

```bash
.venv/bin/python -m pytest tests/test_agent.py tests/test_agent_chats.py tests/test_agent_notes.py tests/test_agent_compaction.py tests/test_server.py -q
npm run check
npm run build
PATH="$PWD/.venv/bin:$PATH" npm run test:ui
```

Серверные и браузерные тесты используют настоящий цикл Nemor и управляемую
тестовую completion-функцию на временных книгах. Проверяются чтение → правка
→ ответ, конфликт с внешней записью, изоляция, остановка, повтор ID,
сохранение разговора, контекст и обновление viewer. HTTP-адаптер проверяется
через MockTransport. Без Nemor интеграционные сценарии явно пропускаются.
Реальная локальная LLM пока не проверена: нужен настроенный endpoint/model;
успех этих тестов не подтверждает качество работы конкретной модели.
