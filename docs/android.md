# Android-приложение Grim

Приложение `dev.mirmik.grim` использует тот же Svelte viewer, что и web-версия.
Опыт Android-оболочки Tauri взят из llm-coreader. Python на телефоне не нужен.

## Подключение к библиотеке

На стартовом экране укажите полный адрес своего сервера Grim, например
`https://reader.example.org/grim/`, и нажмите «Подключиться». HTTP тоже
поддерживается. Адрес сохраняется на устройстве; при следующем запуске его
можно открыть одним нажатием или изменить. Ссылка с `?book=…` открывает
библиотеку по тому же адресу, без сохранения конкретной книги в настройке.

Серверная читалка открывается внутри приложения. Доступны актуальные книги,
заметки, импорт EPUB, рабочие копии и чат с агентом. Изменения книг не требуют
пересборки APK. Для этого режима нужен доступ к серверу. Позиция чтения, тема
и размер текста сохраняются в WebView; браузер телефона хранит свои настройки
и позиции отдельно. Заметки остаются в папке книги на сервере.

Системная кнопка «Назад» закрывает меню/панель, затем возвращает из книги в
библиотеку, а из серверной библиотеки — к выбору адреса. Если сервер недоступен
или адрес ошибочен, «Назад» также позволяет вернуться к настройке подключения.
Со стартового экрана «Назад» закрывает приложение.

Ниже подключения находятся книги на устройстве. Демо, KaTeX, шрифты и его
ресурсы включены в APK и доступны без сети. Скачивание серверных книг для
автономного чтения ещё не реализовано.

## Отдельный вход по токену

В текущей установке работает отдельный HTTPS-порт **8444**:
`https://192.168.0.61:8444/` внутри сети и
`https://95.165.81.109:8444/` снаружи через проброс TCP-порта на роутере.
Этот вход открывается в корне, без `/grim/`. Старый `/grim/` через Reproxy
продолжает работать со своей прежней авторизацией.

При первом подключении введите **токен доступа**. Приложение сохраняет адрес,
а сервер выдаёт защищённую HttpOnly-сессию на 30 дней. Сам токен не сохраняется
в localStorage приложения; Android Keystore и вход по паролю не используются.
Сеанс переживает обычный перезапуск приложения.
Оба адреса, вход и сохранение сеанса после принудительной остановки проверены
на OnePlus 5 / Android 10 с APK 0.2.2.

### Управление устройствами из веб-библиотеки

В основной веб-библиотеке (`/grim/` через прежний Reproxy или LAN-вход
на 8000) нажмите **«Токены доступа»**. Введите название устройства,
например «Основной смартфон», и нажмите «Создать токен». Скопируйте значение
и введите его в приложении. Полный токен показывается только при создании;
после закрытия панели восстановить его нельзя — можно создать новый.

В списке видны название, дата создания, последнее использование и статус.
«Отозвать» отключает токен, его сеансы и ссылки ресурсов книги при следующих
запросах. Остальные устройства продолжают работать. Уже загруженные страницы
остаются в памяти браузера. Перезапуск сервера не восстанавливает отозванный доступ.

Управление доступно через основной доверенный веб-канал. Клиентский вход
8444 не показывает эту панель и не разрешает управляющие API даже с верным
токеном. Существующие защиты Host, Origin и viewer-заголовок действуют и здесь.

Реестр `~/.config/grim/access-tokens.json` (0600) содержит хеши SHA256 и
метаданные, без исходных значений новых токенов. Путь можно переопределить
через `GRIM_ACCESS_TOKENS_FILE`. Отдельный `access-tokens.key` (0600) хранит
серверный секрет подписи, не известный владельцам токенов; сохраняйте его вместе
с реестром. Файл реестра заменяется атомарно. Первоначальный
токен переносится в список без изменения значения и без сброса прежних сеансов;
его также можно отозвать. Файл `mobile-access.token` остаётся секретом подписи
сервера: после отзыва первоначального доступа его не нужно удалять.

Сертификат нового порта содержит IP в SAN и подписан существующим частным CA.
Публичный сертификат CA включён в Android Network Security Configuration
только для `95.165.81.109` и `192.168.0.61`; проверка сертификата и имени/IP
остаётся включённой. Старый сертификат Reproxy и ключ CA не изменяются.

### Настройка сервера

Дополнительный слушатель работает **в том же процессе Grim**, с общей
библиотекой, агентом и блокировками файлов. TLS завершается непосредственно
в Grim на `192.168.0.61`, отдельный прокси не нужен. Переменные окружения:

```text
GRIM_MOBILE_HOST=192.168.0.61
GRIM_MOBILE_PORT=8444
GRIM_ACCESS_TOKEN_FILE=/home/mirmik/.config/grim/mobile-access.token
GRIM_MOBILE_TLS_CERT=/home/mirmik/.config/grim/tls/server.pem
GRIM_MOBILE_TLS_KEY=/home/mirmik/.config/grim/tls/server.key
```

Файл токена должен принадлежать пользователю службы и иметь права `0600`.
Нужен случайный токен не короче 32 байт; его значение не должно попадать в
команды, журнал или репозиторий. Замена файла токена с перезапуском Grim
отзывает прежние сеансы и ссылки чтения.

Закрытый ключ сервера создан на `.61`, принадлежит пользователю службы и имеет
права `0600`. На `.81` передан только CSR для подписи существующим CA; ключ CA
остался на `.81`. `server.pem` содержит leaf-сертификат и цепочку CA.
Переменные настроены в `~/.config/systemd/user/grim.service.d/mobile-access.conf`.
Адреса с портом 8444 добавляются в `GRIM_ALLOWED_ORIGINS`, нужные IP — в
`GRIM_ALLOWED_HOSTS`. Основной HTTP8000 и прежний Reproxy/HAProxy продолжают
работу. На прямом TLS-слушателе заголовки `X-Forwarded-*` не используются.

Без токена нельзя читать библиотеку, API или книги. Внешний клиент может
передавать токен в `Authorization: Bearer …`; браузер использует сессию.
Изолированные страницы книг получают суточные ссылки, разрешающие чтение
только ресурсов одной книги. Поэтому формулы, шрифты и видео работают без
выдачи книжному JavaScript доступа к API или авторизованного CORS для `Origin: null`.
Журнал запросов дополнительного слушателя отключён, чтобы не сохранять такие ссылки.

### Возврат ответов через роутер

На `192.168.0.61` обычный маршрут по умолчанию идёт через `192.168.0.81` и VPN.
Ответы HTTPS на входящие соединения должны возвращаться через обычный роутер
`192.168.0.1`. Для этого используется отдельное правило маршрутизации
`ip rule … ipproto tcp sport 8444 lookup 1061` с приоритетом `10067`.
Таблица `1061` содержит маршрут локальной сети и default через `192.168.0.1`
по `enp197s0` с исходным адресом `192.168.0.61`.

Это тот же механизм, что у Migi на этой машине: его NetworkManager dispatcher
`90-migi-routing` выбирает таблицу `1061` для ответов UDP8443/TCP8790.
Конфигурация Poland3, его hooks и сохранённые iptables для Grim не меняются.

Скрипт [92-grim-routing](../deploy/networkmanager/92-grim-routing) устанавливается
на `.61` в `/etc/NetworkManager/dispatcher.d/` с владельцем `root:root` и правами
`0755`. Он восстанавливает маршруты после подключения LAN/VPN, не перезапускает
VPN и не дублирует правило при повторном запуске. Требуется однократный `sudo`:

```bash
sudo install -o root -g root -m 0755 /home/mirmik/project/grim/deploy/networkmanager/92-grim-routing /etc/NetworkManager/dispatcher.d/92-grim-routing
sudo /etc/NetworkManager/dispatcher.d/92-grim-routing enp197s0 up
```

После применения проверить внешний HTTPS и `scripts/android-token-smoke.mjs`
с `GRIM_TEST_SERVER=https://95.165.81.109:8444/`. Отдельно нужен проброс
TCP 8444 → `192.168.0.61:8444` на роутере.
Для проверки выбранного маршрута:

```bash
ip rule show
ip route get 1.1.1.1 from 192.168.0.61 ipproto tcp sport 8444 dport 443
```

Ожидается `via 192.168.0.1 dev enp197s0 table 1061`; запрос с другим исходным
портом должен по-прежнему выбирать обычный маршрут через `.81`.

## Сборка

Нужны Node.js, Rust с целевой платформой `aarch64-linux-android`, Java 17+
и Android SDK/NDK. Android-проект уже находится в репозитории: повторный
`tauri android init` не требуется. Общие требования — в
[документации Tauri](https://v2.tauri.app/start/prerequisites/#android).

```bash
npm ci
export ANDROID_HOME="$HOME/Android/Sdk"
export NDK_HOME="$ANDROID_HOME/ndk/27.2.12479018"
npm run android:build
```

Команда собирает ARM64 debug APK, подписанный стандартным Android debug-ключом
сборочной машины, для локальной отладки.

Результат: `src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk`.
Для эмулятора можно собрать обе архитектуры:

```bash
npm run tauri -- android build --apk --debug --target aarch64 x86_64 --ci
```

### Подписанный релиз для Migi

```bash
npm run android:release
```

Результат: `src-tauri/gen/android/app/build/outputs/apk/universal/release/app-universal-release.apk`.
Gradle читает подпись из `~/.local/share/grim/signing/release.properties` или
файла, заданного `GRIM_ANDROID_SIGNING_PROPERTIES`. В нём находятся `storeFile`,
`storePassword`, `keyAlias`, `keyPassword`; значения не входят в репозиторий.
Без этого файла Gradle собирает неподписанный APK, который нельзя публиковать.

По разрешению пользователя 2026-10-20 создан отдельный постоянный ключ Grim:
`~/.local/share/grim/signing/grim-release.p12`, alias `grim`. Каталог имеет права
`0700`, ключ и properties — `0600`. SHA256 сертификата подписи:
`483f0ec4e6c03f3133bba6a70012a33ea8780d1946de02a76fbae41bb744a67e`.
Ключ Migi не менялся и для Grim не используется.

В этом же закрытом каталоге находится `grim-release-recovery.tar.gz` с ключом
и настройками для восстановления. Это локальный набор восстановления;
независимая резервная копия требует отдельного защищённого места. Его нельзя
отправлять вместе с APK или публиковать. Для всех следующих обновлений Grim
нужен этот же ключ. Debug и release имеют разные подписи: Android не обновит
установленный debug APK поверх release или наоборот.

Перед публикацией проверять `apksigner verify --print-certs`, пакет
`dev.mirmik.grim`, возрастающий versionCode, ABI, размер и SHA256 APK.
Для доставки использовать скилл `migi-android-publisher`: успешная публикация
создаёт приложение в Migi Updates, затем пользователь подтверждает установку
на телефоне.

## Какие книги попадут в приложение

По умолчанию включено демо «Математика движения». Дополнительные книги задаются
явно через `GRIM_ANDROID_BOOKS`: JSON-массив объектов с `id` и `root`.
Используйте устойчивый ID из `~/.grim/library.json`, чтобы обновление APK
сохраняло место в книге. `root` — путь к папке с `book.json` на сборочной машине.

```bash
export GRIM_ANDROID_BOOKS='[{"id":"0123456789abcdef0123456789abcdef","root":"/absolute/path/to/book"}]'
npm run android:build
```

Сборка копирует снимок папок; исходные книги не изменяются. Скрипт упаковки
проверяет оглавление, уникальность ID, пути страниц и отвергает симлинки.
Скрытые файлы, `node_modules`, `__pycache__` и `*.tmp` не включаются. Остальные
ресурсы папки входят в APK, поэтому перед сборкой выбирайте именно папку книги.
HTML получает общий `bridge.js` для навигации и контекста чтения.
Пути сборочной машины и серверный токен не входят в каталог приложения.

## Проверка

```bash
npm run check
npm run build:android
npx playwright install chromium
npm run test:android-ui
```

Посмотреть автономную сборку в браузере: `npm run preview:android`, адрес
`http://127.0.0.1:1420`. Это локальный просмотр того же содержимого; браузер
должен иметь доступ к preview-серверу, а установленному APK сервер не нужен.

Для native smoke запустите Android-эмулятор и установите debug APK:

```bash
adb -s emulator-5554 install -r src-tauri/gen/android/app/build/outputs/apk/universal/debug/app-universal-debug.apk
node scripts/android-smoke.mjs
```

Для проверки сервера дополнительно запустите одноразовую тестовую библиотеку
и настройте доступ к ней из Android (не используйте настоящие книги для
сценариев, изменяющих данные):

```bash
PATH="$PWD/.venv/bin:$PATH" python3 scripts/serve_test_book.py
# В другом терминале:
adb -s emulator-5554 reverse tcp:8001 tcp:8001
node scripts/android-server-smoke.mjs
```

Для отладочного телефона задайте его serial через `ANDROID_SERIAL`, а в
команде `adb reverse` замените `emulator-5554` тем же serial. Проверка сервера
охватывает подключение, контекст агента, открытие чата, холодный перезапуск,
позицию, системную кнопку «Назад», восстановление после ошибки подключения
и отсутствие native-доступа у серверного документа.

Проверка настоящего HTTPS-входа по токену не меняет книги. Она проверяет
библиотеку, изоляцию страницы и сохранение сеанса после принудительной остановки:

```bash
ANDROID_SERIAL=51f4becc \
GRIM_TEST_SERVER=https://192.168.0.61:8444/ \
GRIM_TEST_TOKEN_FILE=/home/mirmik/.config/grim/mobile-access.token \
node scripts/android-token-smoke.mjs
```

Значение токена читается из файла; в аргументы команд и вывод оно не попадает.

Скрипт проверяет шрифты формул, выделение, перезапуск Android-процесса,
восстановление позиции, интерактивность, изоляцию страницы и системную кнопку
«Назад». Иной эмулятор задаётся переменной `ANDROID_SERIAL`. Скриншоты —
в `test-results/android-native/`. Проверку видео и поворота экрана выполняйте
на книге с соответствующими материалами и целевом устройстве.

## Границы прототипа

- Серверные книги доступны по сети без пересборки APK. Для автономного режима
  книги пока включаются при сборке; скачивание и обновление книг — следующий этап.
- Позиции сохраняются в WebView отдельно по ID книги, переживают закрытие
  приложения и его обновление с той же подписью. Удаление приложения или
  очистка его данных удаляет позиции. Между устройствами они не передаются.
- В серверном режиме выделение и видимый текст передаются серверу и доступны
  внешнему и книжному агентам. В автономном режиме контекст остаётся локальным.
- EPUB и чат работают через сервер. Автономный импорт EPUB/FB2 и перенос
  остальных возможностей Coreader ещё не реализованы.
- Скачивание вложений в общую папку Android ещё не реализовано.
- Полноэкранный режим видео пока не поддерживается Android-оболочкой Tauri.
  Встроенное MP4-видео с защищённого сервера проверено на OnePlus 5 / Android 10:
  кадры 1920×1080, время воспроизведения растёт, ошибок декодирования нет.
  Проверка была без звука; звук и полный пользовательский сценарий остаются
  в #2379. При открытии ролика тестовый x86_64-эмулятор завершался с SIGSEGV
  в двух программных графических режимах.
- HTML остаётся в `iframe sandbox` без `allow-same-origin`. Книжный CSP
  запрещает сетевые запросы; у оболочки нет разрешённых native-команд.

Развитие единой системы ведётся на [доске Grim](http://localhost/board/21),
общее направление — [#2375](http://localhost/task/2375).
